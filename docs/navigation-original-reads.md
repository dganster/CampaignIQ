# Reuse original reads within verified snapshots

Baseline: 004e1dac3bd6efcdc548e2859ad7f2e404e99cf1. The real signed-in Campaigns timing measured 6.4739 seconds, including 4.0465 seconds for the account snapshot. It recorded 130 ImportDraftRepository.document calls consuming about 0.61 seconds. Eight schema validations computed the base catalog digest sixteen times; base catalog work consumed about 0.87 seconds. Nested timings overlap and are not additive speed estimates.

Deployment sessions now retain successful exact document tuples by workspace, draft and role only after confirming read-only repeatable-read mode. Every hit checks active session and transaction failure state. Missing documents and errors are not cached. Writable and read-committed sessions continue to query the repository. New navigations create new sessions, reauthorize and obtain current originals. The per-session cache holds at most 128 entries and 32 MiB of source bytes and metadata; LRU eviction and oversized-document bypass keep it bounded. No result or authorization cache spans requests. Receipt, original hash, account identity and financial replay checks still run on the returned bytes.

For read-only deployment directory connections, schema verification confirms transaction mode and passes the base catalog digest it just computed into the complete role/catalog signature. The schema ACL and column ACL queries, migration ledger comparison, catalog algorithm and expected policy signatures are unchanged. This removes a duplicate eight-query digest calculation within that same repeatable snapshot. Writable/default callers keep the previous computation path; no schema result is retained for another invocation or transaction.

Tests cover repeated originals, new sessions and scopes, missing documents, expiry, SQL failure, writable/read-committed behavior, memory/entry bounds, identical role/catalog signatures and changed ACL detection. Full regression tests and actual disposable PostgreSQL rehearsal are required before release. No stored source, financial generation, role, grant, schema or deployment change is made by the development installer. Candidate and browser timings must be measured before claiming a navigation improvement.
