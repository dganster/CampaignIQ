# Internal crypto monthly writer

This development checkpoint connects the approved crypto candidate to the full
monthly engine. The ordinary strict importer is unchanged unless the internal
account writer supplies a freshly rebuilt, verified candidate. The engine keeps
crypto applicable and processes securities and Forex normally. Futures use the
existing verified projection while crypto row identities come from the complete
original export.

The crypto financial artifact retains original export observations, all original
warnings and controls, the complete approved calculation, documented FIFO lots,
and a separate statement-policy status. Approval never changes a failing export
cash control into a passing one. Fees already included in statement purchase
cash are counted once. Crypto realized sales and value changes remain separate
from securities/futures campaign performance.

All financial artifacts are staged in memory, loaded through canonical account
readers, and checked against the exact current originals and owner receipt.
The publication receipt binds both the candidate and financial artifact hashes.
The restricted SQL writer inserts the entire generation in one transaction and
writes the visibility marker last. Existing artifacts cannot be replaced.

Account results and dashboard loading recheck the crypto descriptor and rebuild
the financial component from approved sources. Missing or conflicting embedded
evidence, descriptors, originals or calculations withhold the complete result
without repair. Published ending lots remain available as the next opening
inventory; subsequent-month approval and source policy remain required.

The `--crypto-source-receipts` LOCAL disposable clone rehearsal now also exercises
the crypto writer: failures after component, receipt and marker inserts; caught
forbidden SQL; independent concurrent duplicate publication with one winner;
invisible uncommitted results; independent results/history/next-opening reads;
and committed corruption rejection. Existing copied financial rows and the
retained restore are checked independently and the disposable clone is removed.

The full engine unit tests additionally run securities, ES futures/options and
approved crypto in one generation. No production deployment or publication is
performed. Public futures and approved-crypto publication guards remain closed.
Application/UI integration and release verification remain pending.
